# Publish complete responses through preallocated native slots

Eligible complete final responses use a fixed-capacity response ring allocated with each H2O response receiver. The handler virtual thread claims a slot, packs bounded headers and the body into its preallocated native storage, and publishes the result. Claim, publish, and abort are short native operations with fixed retry limits. They do not wait. A packing or publication failure aborts the claim. Publishing wakes the event-loop worker, which drains ready slots and validates each scalar request identity. H2O reads the body directly from the slot, and headers are copied into the request pool. Native request cleanup releases the slot, not the return from the final send.

The direct path applies only to eligible complete final responses: status 200 to 999, and a nil, byte-array, ByteBuffer or string body. A supported body that exceeds fixed-body limits uses the ordered native-chunk path. An eligible ordinary Ring response parks on a lock-free queue until a slot is free. Each freed slot wakes one waiter, and the event-loop thread takes no lock to wake it. Exhaustion does not select another payload allocation. Nonblocking admission reports full instead. Informational responses and subsequent final output use the ordered native-chunk path, preserving response order. Fixed slots and streaming blocks have separate storage, and the fixed-slot scan never consumes a streaming queue.

Slots move through `FREE → CLAIMED → READY → IN_NATIVE → FREE`. Each request context holds a typed slot pointer and its claim token before native entry. Cleanup detaches that pair, validates it, updates retained accounting and then makes the slot free. A final send may synchronously dispose the request and let another producer reclaim its slot, so the sender never reads or releases the old slot after that call. Duplicate cleanup has no attached slot to release. A token mismatch is an internal error.

Ready discovery uses a capacity-sized array of atomic 64-bit words, not a full slot scan. Publication releases the READY state before releasing its index bit. The worker acquires and clears each word before visiting its set bits; publication during processing remains for a later visit. Only discovery consumes READY slots, so a delayed bit publisher cannot refer to an already recycled slot. Producer-use protection lasts through bit publication. The ready count includes publications whose bit is not yet visible, and destruction requires empty bitmap words.

Ready slots and retained slots have separate counts. Only ready work influences worker polling. Retirement accounts for claimed, ready and retained slots, plus producer-use references. The producer acquires a reference during a short receiver-admission check, then releases the receiver lock before filling storage. Publication or abort ends that reference. Disconnect cannot reclaim a private slot while its producer writes. A stalled producer or incomplete native cleanup delays retirement rather than allowing storage to be freed.

Complete native producers use a confined FFM view of the claimed slot. The callback runs synchronously without a receiver or lifecycle lock, and the view closes before publication. Java buffer aliases that the caller keeps cannot access the slot after the callback returns. An ordinary Ring return on the direct path needs no streaming controller or receipt. Ring returns that do not qualify use the ordered native-chunk path with a writer and an internal receipt.

The direct path requires neither per-response native payload allocation nor the H2O response-message mutex. Each worker has `:fixed-response-slots` slots, 256 by default. Eligible bodies fit both `:output-buffer-size` and `:fixed-response-max-body-size`, 32768 bytes by default. Supported bodies beyond those limits use the ordered streaming path. A slot holds a head of at most 64 header pairs and 16384 bytes of staging. A larger head uses the ordered streaming path.
